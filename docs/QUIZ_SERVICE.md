# Квиз-сервис

Квизы — отдельный сервис: свой контейнер (`anyq-quiz`, порт 8100 внутри сети),
свои коллекции, свои WebSocket-каналы. С кодом бэкенда он ничего не делит.
На фронтенде квизы — отдельный модуль `frontend/src/quiz/`, который грузится
своим чанком.

```
                 ┌─────────────── nginx (frontend) ───────────────┐
 браузер ───────►│ /api/quiz/*  /api/play/*  /ws/quiz/*  ──► quiz │
                 │ /api/*  /ws  /media                    ──► backend
                 └────────────────────────────────────────────────┘

 quiz ──GET /api/auth/me (cookie)──► backend        кто учитель
 editor ──POST /api/quiz-drafts──► backend ──WS──► agent   кто пишет вопросы
 backend ──account_events (outbox)──► quiz          аккаунт удалён
```

## Границы

| Что | Как пересекает границу | Почему так |
|---|---|---|
| Кто учитель | quiz пересылает cookie в `GET /api/auth/me` бэкенда, ответ кэширует на 30 с | схема аккаунтов принадлежит бэкенду; quiz не читает его таблицы |
| Генерация вопросов | редактор → `POST /api/quiz-drafts` (бэкенд) → агент; результат сохраняется в quiz | ключи моделей только у агента; у quiz их нет и он к ним не ходит |
| Удаление аккаунта | бэкенд пишет `account_deleted` в `account_events` в том же запросе; quiz читает и удаляет квизы, сессии, ответы | outbox: удаление не «наполовину», даже если quiz в этот момент лежит |
| Ученики | без аккаунта: код сессии + имя → токен в `X-Player-Token` | на урок за 10 минут не регистрируют 30 детей |

## Данные (MongoDB, общая база, свои коллекции)

- `quizzes` — квиз учителя: вопросы, настройки.
- `quiz_sessions` — один запуск. Хранит **снимок** вопросов: правка квиза во
  время игры не меняет игру. `live_code` есть только у открытой сессии
  (уникальный sparse-индекс) — код освобождается при завершении.
- `quiz_players` — ученик в сессии: порядок вопросов и вариантов (перемешан для
  каждого), ответы, очки. Токен хранится только хэшем.

## Правила, которые держит сервер

- Ученик получает только текущий вопрос, без ответа и без заметок о заблуждениях;
  правильный ответ — только после своего ответа и только если учитель включил
  «показывать ответ».
- Ответ засчитывается один раз (атомарное условие «ещё не отвечен»), только на
  текущий вопрос и только до дедлайна (+3 с на сеть).
- Время — серверное: в каждом состоянии есть `serverNow`, телефон считает
  смещение. Старт — момент в будущем (обратный отсчёт 4 с), одинаковый для всех.
- Код — 6 символов из алфавита без двойников (нет 0/O, 1/I/L, 2/Z, 5/S, 8/B).

## Масштабирование

Сейчас одна реплика. Для второй нужно вынести в общее хранилище две вещи,
обе локализованы в одном модуле:

- `quiz_service/hub.py` — рассылка событий по сокетам → Redis pub/sub;
- `quiz_service/limits.py` — счётчики лимитов → Redis.

Всё остальное состояние уже в MongoDB, и nginx резолвит `quiz` на каждый
запрос, так что `docker compose up --scale quiz=N` после этих двух шагов
работает без других изменений.

## Тесты

- `tests/quiz/` — сервис целиком на mongomock: вопросы и проверка ответов,
  CRUD и права, игра, часы, результаты, WebSocket, outbox, маршруты nginx.
- `tests/agent/test_quizzes.py` — проверки того, что пишет модель.
- `tests/backend/test_quiz_drafts.py` — эндпоинт черновиков и outbox.
- `tests/e2e/test_quiz_live.py` — полный прогон через nginx на живом стеке.
