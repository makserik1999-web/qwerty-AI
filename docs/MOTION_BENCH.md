**Что сравнивали:** весь пайплайн агента — LLM, guard'ы, озвучка Azure, рендер — без слоя (`MOTION_LAYER=0`, `MOTION_METRIC=1`) и со слоем (`MOTION_LAYER=1`).

- **Кадр больше не стоит.** Было: 81–90% времени на экране неподвижный кадр. Стало 0% во всех 10 роликах.
- **Рендер дольше в 1,5 раза** (+52%): 0,36 → 0,56 секунды рендера на секунду видео. Паузы теперь рисуются покадрово, а не одним кадром.
- **Вся генерация** (LLM, озвучка, рендер) в среднем 82 → 87 с на вопрос. Рендер — меньшая часть ожидания.
- **Файлы вдвое тяжелее:** в среднем 1,14 → 2,01 МБ, потому что движущиеся частицы стоят битрейта.
- **Надёжность не пострадала:** 10/10 до и 10/10 после, все с первой попытки рендера, без ремонтов.
- **Переходы.** Без слоя в скриптах 17 смен «всё погасло — всё появилось», со слоем 5. Кроме того, guard при генерации превратил 11 пар «погасло → появилось» в морфинг (темы 5 и 7). Остальное модель сделала сама по правилу L8. Оставшиеся 5 — группы и подписи без пары «формула → формула» или «фигура → фигура», механически их не переделать.
- **Подсветка формул.** `read_formula` модель вызвала в 9 роликах из 10. Тайминги слов от Azure пришли для всех строк озвучки: 56 из 56, ни одного отката на REST.

Скрипты до и после — разные: модель пишет новый скрипт на каждый запуск. Поэтому длина и содержание у пары немного различаются, сравнение — по пайплайну целиком.

## Как повторить

```bash
# в корне репозитория, ключи в .env; вопросы — по одному на строку
docker run --rm --env-file .env -e MOTION_LAYER=0 -e MOTION_METRIC=1 \
  -e MANIM_OUTPUT_DIR=/tmp/media/outputs -e ANYQ_TELEMETRY_PATH=/bench/runs.jsonl \
  -v "$PWD/agent:/app:ro" -v "$PWD/bench:/bench" --entrypoint python \
  qwerty-ai-agent:latest scripts/motion_bench.py before /bench/questions.txt /bench
# то же с -e MOTION_LAYER=1 и режимом after
```

Ролики и скрипты складываются в `bench/<режим>/NN.mp4|.py`, строки результатов — в `bench/<режим>.jsonl`. Каждый вопрос стоит столько же вызовов модели и символов Azure, сколько настоящий запрос.
