# Деплой: домашний сервер за Cloudflare Tunnel

Весь стек работает на одном домашнем сервере с Docker. Используется тот же `docker-compose.yml`, что и локально, плюс прод-слой `docker-compose.prod.yml`. Белый IP не нужен, порты наружу не открываются. Контейнер `cloudflared` сам подключается к Cloudflare, и запросы посетителей приходят по этому соединению.

```
браузер ──https──► Cloudflare ──туннель──► cloudflared ──http──► frontend:80 (nginx)
                   (TLS, сертификат,                              ├─► backend ─► mongo
                    Always Use HTTPS)                             ├─► quiz
                                                                  └─► /ws/agent → 403
     agent ◄─ws─ backend      exporter      backup ─► /var/backups/anyq
     cron: deploy/monitor.sh ─► Telegram
```

- **HTTPS** обеспечивает Cloudflare, сертификат он тоже продлевает сам. Сам nginx работает только по HTTP на порту 80.
- **Cookie сессии** получает флаг `Secure` от настройки `COOKIE_SECURE=1`.
- **IP посетителя** nginx берёт из `CF-Connecting-IP`. Без этого все пользователи делили бы одни лимиты на вход и регистрацию.
- **Порт `127.0.0.1:8080`** открыт только на самом сервере. Через него можно проверить сайт в обход Cloudflare.

## Сервер

| Параметр | Значение |
|---|---|
| ОС | Debian 12 |
| Процессор | Intel i3-3240 (Ivy Bridge, 2 ядра / 4 потока) |
| Память | 8 ГБ |
| Диск | HDD |
| Сеть | Wi-Fi, без белого IP |
| Фаервол | ufw разрешает только OpenSSH, доступ к серверу через Tailscale |

**Почему mongo 7.** У этого процессора есть AVX, но нет AVX2, поэтому mongo 8 на нём не запускается. Во всех трёх местах (`mongo`, `backup`, `restore`) закреплена версия `mongo:7.0.43`.

Проверить AVX можно командой `grep -o -m1 avx /proc/cpuinfo`, она должна напечатать `avx`.

## В панели Cloudflare (один раз)

1. **Туннель.** Откройте Zero Trust → Networks → Tunnels → ваш туннель.
   - В маршруте (Published application route) должно быть: `akronustaz.com` → **HTTP** → `frontend:80`. Это уже сделано.
   - Токен: в инструкции по установке коннектора (Docker) скопируйте длинную строку после `--token`. Она пойдёт в `TUNNEL_TOKEN` в `.env`. **Это секрет:** с ним кто угодно сможет принимать трафик вашего домена.
2. **SSL/TLS → Edge Certificates → Always Use HTTPS** — включено (уже сделано).
3. **Network → WebSockets** — должно быть включено (по умолчанию так и есть). Без этого не будут работать квизы и прогресс генерации.
4. **Rocket Loader** (Speed → Optimization) — оставьте выключенным. Он вставляет на страницу свой скрипт, а наша политика безопасности (CSP) разрешает только свои скрипты, и сайт сломается.
5. **www.akronustaz.com** пока не настроен. Позже можно добавить в Cloudflare правило перенаправления на основной домен.

## На сервере: первый запуск

Все команды выполняются под root (`sudo -i`).

**1. Docker** нужен из репозитория Docker, а не пакет `docker.io` из Debian: требуется Compose 2.24.4 или новее. Проверка:

```bash
docker compose version
```

Если версия старее или команды нет, установите по инструкции https://docs.docker.com/engine/install/debian/.

**2. Код.** Ключ этого сервера уже добавлен в репозиторий как deploy key только на чтение.

```bash
git clone -b feat/f0-frontend-merge git@github.com:makserik1999-web/qwerty-AI.git /opt/anyq
cd /opt/anyq
```

**3. Подготовка сервера.** Скрипт создаёт swap 4 ГБ, если его нет, каталог `/var/backups/anyq` и задание cron для мониторинга. Фаервол, ssh и Tailscale он не трогает.

```bash
bash deploy/prepare-server.sh
```

**4. Файл `.env`.** Скрипт генерирует пароли базы и секрет агента и записывает домен, `COOKIE_SECURE=1` и `EFFORT_DEFAULT=low`.

```bash
bash deploy/init-env.sh akronustaz.com
nano .env
```

Руками нужно вписать `TUNNEL_TOKEN`, `OPENROUTER_API_KEY`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` и, если хотите получать тревоги, `TELEGRAM_*`.

**5. Запуск.** Скрипт проверяет `.env`, собирает образы, поднимает стек и ждёт, пока все сервисы станут healthy. Потом проверяет сайт двумя способами:
- на самом сервере: сайт, API, квизы, 403 на `/ws/agent`, вебсокет, IP из `CF-Connecting-IP`;
- снаружи через Cloudflare: сайт, API, 403, перенаправление с http на https, вебсокет `wss`, заголовок HSTS.

Первая сборка на i3 с HDD займёт 20–40 минут, почти всё время уходит на образ агента.

```bash
bash deploy/deploy.sh
```

**6. Проверить сайт в обход Cloudflare** со своего компьютера через Tailscale. Откройте туннель и зайдите на http://localhost:8080:

```bash
ssh -L 8080:127.0.0.1:8080 <пользователь>@<имя-сервера-в-tailscale>
```

**7. Тревоги и внешний мониторинг.**
- Проверьте, что тревоги приходят: `bash deploy/monitor.sh --test`.
- Мониторинг работает на самом сервере, поэтому отключение света он не заметит. Заведите бесплатную внешнюю проверку `https://akronustaz.com/` в UptimeRobot или Better Stack.

## Обновление

```bash
cd /opt/anyq
bash deploy/deploy.sh --pull
```

Пересоздаются только изменённые контейнеры: если код не менялся, ничего не перезапускается. Сокеты квизов после перезапуска переподключаются сами. Обновляйте вне уроков.

## Нагрузка на процессор

- **Одна генерация за раз.** Агент берёт задачи из очереди строго по одной. Кроме того, бэкенд не даёт одному пользователю запустить вторую генерацию, пока идёт первая (`GENERATION_MAX_CONCURRENT=1`). Экспорт тоже обрабатывает задачи по одной.
- **Сайт важнее рендера.** У `agent` и `exporter` в prod пониженный приоритет на процессоре (`cpu_shares: 512`), лимиты 2 ядра и 1 ядро. Когда процессор занят, nginx, бэкенд и база получают его первыми.
- **Качество видео.** Для старта стоит `EFFORT_DEFAULT=low` (480p). Замерьте время рендера на сервере, прежде чем переходить на `medium` (720p): он в несколько раз медленнее. После смены значения в `.env` запустите `deploy.sh`.
- **Память базы.** Кэш mongo ограничен 1 ГБ (`--wiredTigerCacheSizeGB 1`), иначе он рассчитывается от всех 8 ГБ машины и не помещается в лимит контейнера.

## Бэкапы

**Что и когда.** Каждую ночь в 02:00 по Астане (`BACKUP_HOUR_UTC=21`) сервис `backup` делает дамп базы. Видео он зеркалирует рядом. Дампы хранятся 14 дней (`BACKUP_KEEP_DAYS`). При первом запуске дамп делается сразу.

**Где лежат.** Всё в `/var/backups/anyq` на хосте, вне томов Docker:
- `mongo/anyq-<время UTC>.archive.gz` — дампы базы;
- `media/outputs/` — зеркало видео;
- `media-removed/<дата>/` — видео удалённых аккаунтов. Они хранятся столько же, сколько дампы, потом стираются.

**Сделать бэкап сейчас:**

```bash
docker compose exec backup bash /opt/anyq/backup.sh once
```

**Восстановить.** Скрипт сначала сделает свежий бэкап и спросит домен для подтверждения.

```bash
bash deploy/restore.sh                                     # список дампов
bash deploy/restore.sh anyq-20261004-210000.archive.gz     # восстановить
```

**Копия вне дома.** Диск сервера может умереть, а вместе с ним и бэкапы на нём. Копируйте папку на другую машину, например через Tailscale:

```bash
rsync -az root@<сервер>:/var/backups/anyq/ ~/anyq-backups/
```

**Перенести базу с другой машины.**

1. На локальной машине, при запущенном стеке, сделайте архив. Папка должна лежать вне репозитория:

   ```bash
   BACKUP_DIR=$HOME/anyq-export docker compose -f docker-compose.yml -f docker-compose.prod.yml run --rm --no-deps backup once
   ```

2. Скопируйте его в `/var/backups/anyq/` на сервере.
3. На сервере запустите `bash deploy/restore.sh <файл>`.

## Мониторинг

Cron каждые 5 минут запускает `deploy/monitor.sh`. Он проверяет:
- все сервисы запущены и healthy, включая связь туннеля с Cloudflare, связь агента с бэкендом и бэкап за последние 26 часов;
- сайт отвечает и на сервере (`127.0.0.1:8080`), и через Cloudflare. По этим двум проверкам видно, где поломка: в сайте или в туннеле;
- диск занят меньше чем на 85%.

Сообщение приходит, когда набор проблем меняется, плюс напоминание каждые 6 часов, пока проблема не ушла. Лог пишется в `/var/log/anyq-monitor.log`.

**Telegram.**
1. Создайте бота у [@BotFather](https://t.me/BotFather) и вставьте токен в `TELEGRAM_BOT_TOKEN`.
2. Напишите боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<токен>/getUpdates` и возьмите оттуда `chat.id` для `TELEGRAM_CHAT_ID`.

Логи Docker у всех сервисов ротируются: не больше 3 файлов по 10 МБ на сервис.

## Полезное

```bash
docker compose ps                      # состояние
docker compose logs -f backend         # логи сервиса
docker compose logs cloudflared        # подключился ли туннель
docker compose restart agent           # перезапустить один сервис
docker image prune -f                  # старые образы после обновлений
```

`COMPOSE_FILE` в `.env` уже включает прод-слой, поэтому флаги `-f` на сервере не нужны.

## Безопасность: чек-лист

- [ ] Старые ключи Azure и OpenRouter отозваны, в `.env` новые.
- [ ] `TUNNEL_TOKEN` есть только в `.env` на сервере. Если он утёк, перевыпустите его в панели туннеля.
- [ ] У `.env` права 600 (`deploy.sh` следит за этим сам).
- [ ] Наружу ничего не опубликовано: `ss -tlnp` показывает только `127.0.0.1:8080` от Docker. ufw не менялся.
- [ ] `deploy.sh` проверил, что `/ws/agent` отвечает 403 и на сервере, и через Cloudflare.
- [ ] Репозиторий **публичный**: код виден всем. Секретов в нём нет (`.env` не попадает в git). Если хотите закрыть код, сделайте репозиторий приватным: deploy key продолжит работать.

## Ограничения и следующие задачи

- **Таймаут Cloudflare 100 секунд (ошибка 524). Это следующая задача.** Cloudflare обрывает HTTP-запрос, если ответ не пришёл за 100 секунд. План урока может готовиться до 150 секунд (обычно около 40), черновик квиза — до 120 секунд. Если генерация затянется, учитель увидит ошибку 524, хотя бэкенд её закончит. Решение: перевести план урока и черновик квиза в фоновые задачи с опросом статуса. Запрос сразу возвращает id задачи, фронтенд раз в несколько секунд спрашивает, готово ли. Генерации видео это не касается, она идёт через вебсокет.
- **Один домашний сервер — одна точка отказа.** Отключение света, интернета или Wi-Fi означает, что сайт недоступен. После включения всё поднимется само (`restart: unless-stopped`). Желательно поставить ИБП и, если возможно, подключить сервер по кабелю.
- **HDD** медленнее SSD: сборка, бэкапы и база работают дольше. Это не критично, но первая сборка долгая.
- **www** пока не настроен.
- **Оплаты нет.** Страница «Баланс» пока на демо-данных.
