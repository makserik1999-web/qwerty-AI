# Деплой: домашний сервер за Cloudflare Tunnel

Весь стек работает на одном домашнем сервере с Docker. Используется тот же `docker-compose.yml`, что и локально, плюс прод-слой `docker-compose.prod.yml`. Белый IP не нужен, порты наружу не открываются. Контейнер `cloudflared` сам подключается к Cloudflare, и запросы посетителей приходят по этому соединению.

```
браузер ──https──► Cloudflare ──туннель──► cloudflared ──http──► frontend:80 (nginx)
                   (TLS, сертификат,                              ├─► backend ─► mongo
                    Always Use HTTPS)                             ├─► quiz
                                                                  └─► /ws/agent → 403
     agent ◄─ws─ backend      exporter      backup ─► /var/backups/anyq
     cron: deploy/monitor.sh ─► Telegram
```

- **HTTPS** обеспечивает Cloudflare, сертификат он тоже продлевает сам. Сам nginx работает только по HTTP на порту 80.
- **Cookie сессии** получает флаг `Secure` от настройки `COOKIE_SECURE=1`.
- **IP посетителя** nginx берёт из `CF-Connecting-IP`. Без этого все пользователи делили бы одни лимиты на вход и регистрацию.
- **Порт `127.0.0.1:8080`** открыт только на самом сервере. Через него можно проверить сайт в обход Cloudflare.

## Сервер

| Параметр | Значение |
|---|---|
| ОС | Debian 12 |
| Процессор | Intel i3-3240 (Ivy Bridge, 2 ядра / 4 потока) |
| Память | 8 ГБ |
| Диск | HDD |
| Сеть | Wi-Fi, без белого IP |
| Фаервол | ufw разрешает только OpenSSH, доступ к серверу через Tailscale |

**Почему mongo 7.** У этого процессора есть AVX, но нет AVX2, поэтому mongo 8 на нём не запускается. Во всех трёх местах (`mongo`, `backup`, `restore`) закреплена версия `mongo:7.0.43`.

Проверить AVX можно командой `grep -o -m1 avx /proc/cpuinfo`, она должна напечатать `avx`.

## В панели Cloudflare (один раз)

1. **Туннель.** Откройте Zero Trust → Networks → Tunnels → ваш туннель.
   - В маршруте (Published application route) должно быть: `akronustaz.com` → **HTTP** → `frontend:80`. Это уже сделано.
   - Токен: в инструкции по установке коннектора (Docker) скопируйте длинную строку после `--token`. Она пойдёт в `TUNNEL_TOKEN` в `.env`. **Это секрет:** с ним кто угодно сможет принимать трафик вашего домена.
2. **SSL/TLS → Edge Certificates → Always Use HTTPS** — включить. 20.10.2026 проверка деплоя показала, что он выключен: `http://akronustaz.com` открывался без перехода на https. Если `deploy.sh` пишет `FAIL 200 (ждали 301) http -> https` — дело в этой настройке, не в туннеле.
3. **Network → WebSockets** — должно быть включено (по умолчанию так и есть). Без этого не будут работать квизы и прогресс генерации.
4. **Rocket Loader** (Speed → Optimization) — оставьте выключенным. Он вставляет на страницу свой скрипт, а наша политика безопасности (CSP) разрешает только свои скрипты, и сайт сломается.
5. **www.akronustaz.com** пока не настроен. Позже можно добавить в Cloudflare правило перенаправления на основной домен.

## На сервере: первый запуск

Все команды выполняются под root (`sudo -i`).

**1. Docker** нужен из репозитория Docker, а не пакет `docker.io` из Debian: требуется Compose 2.24.4 или новее. Проверка:

```bash
docker compose version
```

Если версия старее или команды нет, установите по инструкции https://docs.docker.com/engine/install/debian/.

**2. Код.** Ключ этого сервера уже добавлен в репозиторий как deploy key только на чтение.

```bash
git clone -b feat/f0-frontend-merge git@github.com:makserik1999-web/qwerty-AI.git /opt/anyq
cd /opt/anyq
```

**3. Подготовка сервера.** Скрипт создаёт swap 4 ГБ, если его нет, каталог `/var/backups/anyq` и задание cron для мониторинга. Фаервол, ssh и Tailscale он не трогает.

```bash
bash deploy/prepare-server.sh
```

**4. Файл `.env`.** Скрипт генерирует пароли базы и секрет агента и записывает домен, `COOKIE_SECURE=1` и `EFFORT_DEFAULT=low`.

```bash
bash deploy/init-env.sh akronustaz.com
nano .env
```

Руками нужно вписать `TUNNEL_TOKEN`, `OPENROUTER_API_KEY`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` и, если хотите получать тревоги, `TELEGRAM_*`.

**5. Запуск.** Скрипт проверяет `.env`, собирает образы, поднимает стек и ждёт, пока все сервисы станут healthy. Потом проверяет сайт двумя способами:
- на самом сервере: сайт, API, квизы, 403 на `/ws/agent`, вебсокет, IP из `CF-Connecting-IP`;
- снаружи через Cloudflare: сайт, API, 403, перенаправление с http на https, вебсокет `wss`, заголовок HSTS.

Первая сборка на i3 с HDD займёт 20–40 минут, почти всё время уходит на образ агента.

```bash
bash deploy/deploy.sh
```

**6. Проверить сайт в обход Cloudflare** со своего компьютера через Tailscale. Откройте туннель и зайдите на http://localhost:8080:

```bash
ssh -L 8080:127.0.0.1:8080 <пользователь>@<имя-сервера-в-tailscale>
```

**7. Тревоги и внешний мониторинг.**
- Проверьте, что тревоги приходят: `bash deploy/monitor.sh --test`.
- Мониторинг работает на самом сервере, поэтому отключение света он не заметит. Заведите бесплатную внешнюю проверку `https://akronustaz.com/` в UptimeRobot или Better Stack.

## Обновление

```bash
cd /opt/anyq
bash deploy/deploy.sh --pull
```

Пересоздаются только изменённые контейнеры: если код не менялся, ничего не перезапускается. Сокеты квизов после перезапуска переподключаются сами. Обновляйте вне уроков.

## Нагрузка на процессор

- **Одна генерация за раз.** Агент берёт задачи из очереди строго по одной. Кроме того, бэкенд не даёт одному пользователю запустить вторую генерацию, пока идёт первая (`GENERATION_MAX_CONCURRENT=1`). Экспорт тоже обрабатывает задачи по одной.
- **Сайт важнее рендера.** У `agent` и `exporter` в prod пониженный приоритет на процессоре (`cpu_shares: 512`), лимиты 2 ядра и 1 ядро. Когда процессор занят, nginx, бэкенд и база получают его первыми.
- **Качество видео.** Для старта стоит `EFFORT_DEFAULT=low` (480p). Замерьте время рендера на сервере, прежде чем переходить на `medium` (720p): он в несколько раз медленнее. После смены значения в `.env` запустите `deploy.sh`.
- **Память базы.** Кэш mongo ограничен 1 ГБ (`--wiredTigerCacheSizeGB 1`), иначе он рассчитывается от всех 8 ГБ машины и не помещается в лимит контейнера.

## Слой движения (`MOTION_LAYER`)

Выключен по умолчанию. Когда включён, у каждого нового видео: тёмно-синий «дышащий» фон с частицами и полосой прогресса, фигуры слегка плавают, формулы и фигуры перетекают друг в друга вместо «всё погасло — всё появилось», а в формуле подсвечивается член, который сейчас произносит диктор. Без флага промпт и пайплайн прежние.

- **Включить:** в `.env` поставить `MOTION_LAYER=1` и **в том же деплое** поднять `PIPELINE_VERSION` (например, `v4` → `v5`). Иначе темы из кэша продолжат отдаваться старыми видео без слоя. Потом `bash deploy/deploy.sh`.
- **Выключить:** `MOTION_LAYER=0` и вернуть прежний `PIPELINE_VERSION`.
- **Цена — время рендера.** Паузы теперь рисуются кадр за кадром, а не одним застывшим кадром. Тестовая сцена 32 с на ноутбуке: 480p — 6,8 → 11,9 с, 720p — 17 → 28 с. На сервере замерьте сами (поле `render_seconds` в телеметрии).
- **Метрика.** Со слоем в телеметрии агента (`/app/logs/runs.jsonl`) пишутся `static_share` — доля времени, где кадр стоит (цель — меньше 5%), `static_seconds` и `render_seconds`. Чтобы снять те же цифры без слоя, для сравнения, — `MOTION_METRIC=1`: это ещё один проход ffmpeg по видео, несколько секунд на генерацию.

## Бэкапы

**Что и когда.** Каждую ночь в 02:00 по Астане (`BACKUP_HOUR_UTC=21`) сервис `backup` делает дамп базы. Видео он зеркалирует рядом. Дампы хранятся 14 дней (`BACKUP_KEEP_DAYS`). При первом запуске дамп делается сразу.

**Где лежат.** Всё в `/var/backups/anyq` на хосте, вне томов Docker:
- `mongo/anyq-<время UTC>.archive.gz` — дампы базы;
- `media/outputs/` — зеркало видео;
- `media-removed/<дата>/` — видео удалённых аккаунтов. Они хранятся столько же, сколько дампы, потом стираются.

**Сделать бэкап сейчас:**

```bash
docker compose exec backup bash /opt/anyq/backup.sh once
```

**Восстановить.** Скрипт сначала сделает свежий бэкап и спросит домен для подтверждения.

```bash
bash deploy/restore.sh                                     # список дампов
bash deploy/restore.sh anyq-20261004-210000.archive.gz     # восстановить
```

**Копия вне дома.** Диск сервера может умереть, а вместе с ним и бэкапы на нём. Копируйте папку на другую машину, например через Tailscale:

```bash
rsync -az root@<сервер>:/var/backups/anyq/ ~/anyq-backups/
```

**Перенести базу с другой машины.**

1. На локальной машине, при запущенном стеке, сделайте архив. Папка должна лежать вне репозитория:

   ```bash
   BACKUP_DIR=$HOME/anyq-export docker compose -f docker-compose.yml -f docker-compose.prod.yml run --rm --no-deps backup once
   ```

2. Скопируйте его в `/var/backups/anyq/` на сервере.
3. На сервере запустите `bash deploy/restore.sh <файл>`.

## Мониторинг

Cron каждые 5 минут запускает `deploy/monitor.sh`. Он проверяет:
- все сервисы запущены и healthy, включая связь туннеля с Cloudflare, связь агента с бэкендом и бэкап за последние 26 часов;
- сайт отвечает и на сервере (`127.0.0.1:8080`), и через Cloudflare. По этим двум проверкам видно, где поломка: в сайте или в туннеле;
- диск занят меньше чем на 85%.

Сообщение приходит, когда набор проблем меняется, плюс напоминание каждые 6 часов, пока проблема не ушла. Лог пишется в `/var/log/anyq-monitor.log`.

- **Во время деплоя мониторинг молчит.** `deploy.sh` ставит метку `/var/tmp/anyq-deploying` и убирает её в конце; пока она есть (но не дольше 30 минут), проверки не идут — пересоздание контейнеров не авария.
- **Если сообщение не дошло** (у сервера пропал интернет — Telegram недоступен), оно отправится со следующей проверкой.
- **«Всё снова в порядке»** перечисляет, что было и сколько длилось, — понятно, даже если само сообщение о проблеме не пришло.

**Telegram.**
1. Создайте бота у [@BotFather](https://t.me/BotFather) и вставьте токен в `TELEGRAM_BOT_TOKEN`.
2. Напишите боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<токен>/getUpdates` и возьмите оттуда `chat.id` для `TELEGRAM_CHAT_ID`.

Логи Docker у всех сервисов ротируются: не больше 3 файлов по 10 МБ на сервис.

## Админка

Адрес: `https://akronustaz.com/admin`. У сотрудников в меню пользователя (по аватару) есть пункт «Админка», у остальных его нет. Но защищает не это: бэкенд проверяет роль на каждом запросе к `/api/admin/*` и всем, кроме сотрудников, отвечает 404, даже если адрес известен.

| Роль | Что может |
|---|---|
| `admin` | всё: статистика, метрики с выручкой, пользователи, задачи, система, библиотека, рефералы, платежи, тарифы, кэш ответов, журнал действий |
| `support` | статистика, пользователи (поиск, блокировка, сброс сынақ), задачи с перезапуском, система, библиотека, рефералы. Не видит платежи, тарифы, метрики, кэш и журнал; не выдаёт подписки и видео |

Каждое изменение из админки (подписка, блокировка, платёж, видео, перезапуск задачи) пишется в журнал действий: кто, когда и с какой причиной. Генерации считаются с момента обновления, на котором появилась админка: более ранние дни будут нулевыми.

**Как выдать роль.** Только командой на сервере. Через сайт роль получить нельзя: регистрация, профиль и сама админка поле роли не меняют.

1. Человек регистрируется на сайте как обычно.
2. На сервере:
   ```bash
   cd /opt/anyq
   docker compose exec backend python -m app.staff grant почта@пример.kz --role admin
   ```
3. Команда покажет аккаунт. Проверьте, что он того человека (имя, дата регистрации): почта при регистрации пока не подтверждается, и адрес мог занять кто-то другой. Ответьте `y`.

```bash
docker compose exec backend python -m app.staff list                      # кто сотрудник
docker compose exec backend python -m app.staff revoke почта@пример.kz    # снять роль
docker compose exec backend python -m app.staff reset-link почта@пример.kz  # ссылка для нового пароля
```

**Забыли почту или пароль админа.** `app.staff list` покажет почты всех сотрудников. `app.staff reset-link почта` напечатает одноразовую ссылку для нового пароля (действует час) — откройте её в браузере, задайте пароль, вы сразу войдёте. Почта для этого не нужна; запрос пишется в журнал. Так же можно помочь учителю, которому не приходит письмо: ссылку отдайте только ему лично.

`--reason "..."` добавляет причину в журнал. Выдача и снятие записываются в журнал действий. Снятая роль перестаёт действовать сразу, на следующем же запросе. Сотрудников держите минимум: они видят все аккаунты.

**Cloudflare Access — второй замок.** Пусть посторонний вообще не доходит до `/admin`. Бесплатно до 50 пользователей.

1. dash.cloudflare.com → **Zero Trust**. При первом входе выберите имя команды и план Free.
2. **Access** → **Applications** → **Add an application** → **Self-hosted**.
3. Название `Akron admin`. Добавьте два адреса: домен `akronustaz.com` с путём `admin` и тот же домен с путём `api/admin`. Оба в одном приложении, иначе страница откроется, а данные не загрузятся.
4. Политика: **Allow**, Include → **Emails** → почты сотрудников.
5. Способ входа: **One-time PIN** (код на почту).
6. Проверка: откройте `https://akronustaz.com/admin` в приватном окне. Должна появиться страница Cloudflare с вводом почты. После входа статистика должна загрузиться.

## Аккаунты: почта, Google, телефон

Без настроек всё работает в режиме «лог»: письма и SMS-коды никуда не уходят, а пишутся в `docker compose logs backend`. Так удобно проверять, но учителям нужно настоящее. Ссылки в письмах и адрес возврата от Google строятся из `SITE_DOMAIN` (`PUBLIC_BASE_URL=https://akronustaz.com`), отдельно указывать не нужно.

После любой правки `.env` в этом разделе: `docker compose up -d backend`.

**Почта — нужна для запуска.**
1. Заведите аккаунт у сервиса рассылки с SMTP: Brevo, Resend, Mailgun — подойдёт любой. Бесплатного тарифа на старт хватит.
2. В сервисе добавьте домен `akronustaz.com`. Он покажет DNS-записи (SPF, DKIM, иногда DMARC). Добавьте их в Cloudflare → DNS с серым облаком (DNS only). Без них письма попадают в спам.
3. Впишите в `.env` SMTP-данные из сервиса:
   ```
   MAIL_TRANSPORT=smtp
   SMTP_HOST=...
   SMTP_PORT=587
   SMTP_USER=...
   SMTP_PASSWORD=...
   SMTP_FROM=Akron <no-reply@akronustaz.com>
   ```
4. Зарегистрируйтесь на сайте тестовой почтой: письмо должно прийти. Если нет — `docker compose logs backend | grep mail`.
5. Когда письма доходят, включите `REQUIRE_VERIFIED_EMAIL=1`. С этого момента без подтверждённой почты приложение не открывается: после регистрации и при каждом входе человек видит только страницу «Поштаңызды растаңыз» с кнопками «Растадым», «Қайта жіберу» и «Шығу». Как только ссылка из письма открыта — хоть на телефоне — приложение открывается само. Вход через Google подтверждает почту сразу. Сервер к тому же отказывает в любой генерации неподтверждённому аккаунту. Раньше включать нельзя: письма с ссылкой никто не получит. `deploy.sh` откажется деплоить с `REQUIRE_VERIFIED_EMAIL=1` без SMTP.

**Вход через Google — необязательно.**
1. [console.cloud.google.com](https://console.cloud.google.com) → новый проект «Akron».
2. APIs & Services → **OAuth consent screen**: тип External, название Akron, почта поддержки, домен `akronustaz.com`. Доступы: `openid`, `email`, `profile` — для них проверка Google не нужна. Нажмите **Publish app**, иначе войти смогут только тестовые пользователи.
3. **Credentials** → Create credentials → **OAuth client ID** → Web application. Authorized redirect URI: `https://akronustaz.com/api/auth/google/callback`.
4. Client ID и Client secret — в `.env` как `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Кнопка «Войти через Google» появится на входе и регистрации.

Если Google-почта совпадает с уже существующим аккаунтом, они объединяются. Если тот аккаунт почту не подтверждал, его пароль сбрасывается и все его сеансы закрываются: адрес мог зарегистрировать кто-то чужой.

**SMS для телефона — понадобится для пробного пакета.**
- smsc.kz: `SMS_PROVIDER=smsc`, `SMSC_LOGIN`, `SMSC_PASSWORD`.
- mobizon.kz: `SMS_PROVIDER=mobizon`, `MOBIZON_API_KEY`.
- `SMS_SENDER` — имя отправителя (например, Akron), если провайдер его одобрил; обычно на это нужна заявка. Пусто — имя провайдера по умолчанию.
- `SMS_DAILY_MAX=200` — потолок на весь сайт в сутки, защита от накрутки счёта. Коды уходят только на казахстанские мобильные (+7 7xx).
- Первое настоящее SMS отправьте себе (Настройки → Телефон). Если не пришло: `docker compose logs backend | grep sms` — там будет ответ провайдера (баланс, имя отправителя).

| БЖБ/ТЖБ | 2 | 20 в месяц, остаток переносится | так же |
| Квизы (ИИ-черновик) | 3 | без лимита (честное использование — 100 в месяц) | так же |
| Поурочные планы | 2 | 40 в месяц | так же |
| DOCX | с подписью «Akron арқылы жасалды» | без подписи | без подписи |

- Все цифры и цены хранятся в базе и меняются в админке (вкладка «Тарифы») без деплоя. Лимиты для поурочных планов в задании не были указаны — поставил как у БЖБ; поправьте там же.
- **Пробный пакет** включается сам, когда учитель подтверждает телефон. Один номер — один пакет навсегда: в базе хранится HMAC номера (ключ `PHONE_HASH_SECRET`), и запись остаётся даже после удаления аккаунта. `deploy.sh` один раз сам добавит `PHONE_HASH_SECRET` в `.env` — **не меняйте и не удаляйте его**, иначе все номера снова получат пакет.
- **Ұстаз** считается помесячно с дня подключения. Неиспользованные видео и БЖБ/ТЖБ переходят на следующий месяц (не больше 20 каждого) — БЖБ нужны рывком в конце четверти. «+10 видео» тратятся после месячных.
- **Два варианта БЖБ.** Учитель выбирает «Екі нұсқа» — одна генерация даёт 1-нұсқа и 2-нұсқа: те же навыки и баллы, другие числа. Списывается как один БЖБ. В DOCX и при печати каждый вариант на своём листе.
- **Квизы** на странице «Тариф» — «шексіз», но у Ұстаз есть потолок честного использования — 100 в месяц. Он не тайный: написан под счётчиком и на карточке тарифа. При упоре учитель видит «келесі айда қайта ашылады». Меняется в «Тарифах»; пустое поле — без потолка.
- **На уже работающем сервере** тарифы лежат в базе, и новые цифры из кода их не меняют. Перенос БЖБ и потолок квизов добавятся сами при деплое, а лимит БЖБ 40 → 20 поставьте сами: «Тарифы» → «Ұстаз · ай» и «Ұстаз · оқу жылы» → БЖБ/ТЖБ = 20.
- **Смена тарифа** (месяц ↔ учебный год) — на странице «Тариф» учитель выбирает карточку и жмёт «Ауысу», при ручной выдаче — то же через «Выдать или продлить». Оплаченные дни не пропадают: месяц после года добавляется в конец года, год после месяца длится до 1 июня (или дольше, если месяц кончается позже). Лимит текущего месяца тоже сохраняется: смена тарифа не даёт новых 20 видео.
- **Пауза на лето** — только у помесячного, с 15 мая по август: оставшиеся оплаченные дни продолжатся с 1 сентября. Кнопка на странице «Тариф».
- **Напоминание** — письмо за 3 дня до конца подписки (нужна настроенная почта).
- Готовое видео из библиотеки и неудавшаяся генерация лимит не тратят.
- Подписку можно подключить и вручную — карточка пользователя в админке → «Выдать или продлить», с причиной. Там же: добавить видео, завершить подписку, сбросить пробный пакет, заблокировать. Всё пишется в журнал.

## Оплата через Kaspi

Полуручная: учитель выбирает тариф → видит сумму, номер Kaspi и код вида `AK-7KQ3M` → переводит, вписав код в комментарий → жмёт «Я оплатил». Вам в Telegram приходит сумма и код со ссылкой — она открывает в админке именно этот платёж. Найдите в Kaspi перевод с этим кодом и суммой и нажмите «Подтвердить»; админка ещё раз спросит код и сумму, и тариф включится сам. Код можно и вбить в поле «Код из комментария Kaspi» — как угодно: `AK-7KQ3M`, `ak7kq3m` или `7KQ3M`. Если перевода нет — «Отклонить» с причиной, учитель её увидит. Возврат записывается там же (и снимает тариф или докупленные видео). Работать с платежами может только `admin`.

Пока в `.env` нет реквизитов, кнопки оплаты не показываются — вместо них ваши контакты. Чтобы включить:

```
KASPI_PAY_PHONE=+7 7xx xxx xx xx        # номер, на который переводят
KASPI_PAY_NAME=Иса Ә.                    # имя получателя, как его показывает Kaspi
KASPI_PAY_LINK=                          # необязательно: ссылка Kaspi Pay или страница с QR
KASPI_PAY_NOTE=ИП ..., БИН ...           # необязательно: строка под реквизитами
PAYMENT_NOTIFY_EMAILS=you@mail.kz        # кому писать, когда учитель нажал «Я оплатил»
```

**Уведомления в Telegram.** Когда учитель жмёт «Я оплатил», бот присылает сумму, тариф, код платежа, почту учителя и ссылку прямо на вкладку «Платежи». Это тот же бот, что и для мониторинга сервера:

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и возьмите токен.
2. Напишите своему боту любое сообщение (без этого он не сможет вам писать).
3. Откройте в браузере `https://api.telegram.org/bot<токен>/getUpdates` и найдите `"chat":{"id":...}` — это ваш chat id.
4. Впишите в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   TELEGRAM_CHAT_ID=123456789
   PAYMENT_TELEGRAM_CHAT_ID=                # необязательно: платежи в другой чат, чем сбои сервера
   ```
5. `docker compose up -d --force-recreate backend`, затем проверка:
   ```bash
   docker compose exec backend python -m app.services.telegram
   ```
   Должно прийти тестовое сообщение. Если нет — команда скажет, что не так.

Можно завести группу (вы и тот, кто проверяет Kaspi), добавить туда бота и указать id группы — он начинается с минуса.

Цена фиксируется в момент заказа: если поменять цену в админке, уже выставленные заказы не изменятся. Неоплаченный заказ закрывается через 3 дня (`PAYMENT_REQUEST_TTL_DAYS`). Выручка по месяцам — вверху вкладки «Платежи».

## Темы, кэш видео и видеотека

- **Общий или конкретный вопрос.** Перед рендером бэкенд одним коротким запросом к агенту узнаёт, общий ли вопрос («объясни Пифагора») и к какой теме он относится. Тема выбирается только из фиксированного списка — `agent/anyq/topics.json` (354 темы, 5–11 классы), без эмбеддингов: «теорема Пифагора» и «обратная теорема» — разные темы. Конкретный вопрос (числа, данные, фото, свой пример) всегда рендерится заново.
- **Кэш по темам.** Каждое удачное видео по общему вопросу сохраняется под своей темой и языком — до 3 версий на тему. Следующему, кто спросит то же по-другому, сразу отдаётся лучшая по 👍/👎 версия, лимит не тратится (ученикам тоже). Под таким видео — кнопка «Менің сұрағым бойынша жаңасын жасау»: новый рендер, спишется с лимита.
- **Видеотека.** В меню «Бейнетека» — только видео, которые кто-то из команды проверил и отправил «в витрину». Админка → «Библиотека»: очередь на проверку, «В витрину», «Отклонить» (больше не отдаётся), «Удалить», исправить название и тему, фильтр видео без звука. Это может и `support`.
- **Список тем надо проверить учителю** — я составил его по программе, но не сверял с действующими учебниками. Правьте `agent/anyq/topics.json` и `backend/app/data/topics.json` вместе (тест упадёт, если они разойдутся); id тем не переименовывайте — под ними лежат видео.
- Поиск похожих формулировок по эмбеддингам теперь выключен (`CACHE_SEMANTIC_ENABLED=0`). Кэш точных формулировок работает как раньше.
- **Вертикальные видео.** Рядом с длительностью — «Пішім»: «Көлденең» (16:9, для доски) или «Тік» (9:16, для телефона, статуса WhatsApp, Reels). Вертикальное — не обрезка горизонтального: сцена сразу строится для узкого кадра (части друг под другом, подписи короче), в 1080p это 1080×1920. Вертикальные и горизонтальные видео хранятся раздельно — и в кэше формулировок, и в видеотеке по темам (у каждой ориентации свои 3 места). Плеер сам показывает вертикальное видео стоя, по центру.

### Видео без звука

Если озвучка не сработала (нет ключа Azure, кончилась квота), видео всё равно приходит — немым. Такое видео:
- не попадает в кэш по формулировке вопроса и не отдаётся по теме тем, кто просил озвучку — только тем, кто её выключил;
- видно в админке: «Задачи» → «Только видео без звука», «Система» → счётчик за сутки.

Удалить или отклонить видео во вкладке «Библиотека» — значит убрать его отовсюду, в том числе из кэша по формулировке. Если плохой ответ остался в кэше с более ранних времён:

```bash
docker compose exec backend python -m app.cache_cli forget "Пифагор теоремасы қалай дәлелденеді?"
```

Регистр, пробелы и знаки препинания не важны. Следующий, кто спросит, получит новое видео.

Причину немого видео смотрите в логе агента: `docker compose logs agent --since 3h | grep narration`.

## Рефералы

- У каждого учителя на странице «Тариф» — своя ссылка вида `https://akronustaz.com/signup?ref=K7M2QX`, кнопки «Копировать» и «Поделиться в WhatsApp».
- Приглашённый получает **+2 видео** к пробному пакету (пакет всё равно требует новый номер телефона).
- Код приглашения живёт в браузере **30 дней** и стирается, как только в этом браузере кто-то вошёл или зарегистрировался. Раньше он оставался навсегда: тестер, регистрировавшийся на вашем ноутбуке, видел «вас пригласил коллега» и получал +2 видео. Теперь ещё и сервер не засчитывает приглашение, если новый аккаунт создают в браузере, где входил сам пригласивший.
- Пригласивший получает **+1 месяц Ұстаз**, когда приглашённый впервые оплатил подписку и вы подтвердили платёж. Если у пригласившего идёт годовой тариф — он продлевается на месяц, тариф не меняется. Не больше **6 месяцев за 365 дней**; сверх лимита награда не начисляется, но записывается.
- Админка → «Рефералы» (видит и `support`): кто кого пригласил, оплатил ли, и подсказки злоупотреблений — приглашённый с того же устройства или из той же сети, группы из 3+ аккаунтов на одном устройстве. Хранятся только хэши IP и случайного id браузера, сами адреса — нет. Общая сеть ещё ничего не доказывает: компьютерный класс школы — одна сеть.

## Обратная связь на пилоте

- Под каждым БЖБ/ТЖБ, поурочным планом и квизом от ИИ есть плашка «Мұны жасанды интеллект жазды… тексеріңіз» (при печати не видна) и кнопка **«Қате туралы хабарлау»**. У объяснений кнопка стоит рядом с «Сохранить в библиотеку».
- Сообщение сразу приходит в Telegram (тот же бот, что и для платежей) и попадает в админку, вкладка **«Обращения»**. Разобранное отмечайте кнопкой «Разобрано», это запишется в журнал. Не больше 20 сообщений в день от одного аккаунта.
- **Учитель ошибся ролью при регистрации** (выбрал «Оқушы»): админка → Пользователи → карточка → «Сделать учителем», с причиной. Это может и `support`. Сам человек роль поменять не может.

## Политика конфиденциальности

Страница `/privacy` на казахском и русском, ссылка в подвале сайта. При регистрации нужно отметить согласие; без галочки аккаунт не создаётся. В базе хранится, какую версию политики человек принял и когда. Тот, кто ещё не соглашался (все аккаунты, созданные до этого обновления, и вход через Google со страницы входа), при открытии приложения видит окно «Келісемін / Шығу».

- **Оператор и контакты** — в одном месте: `frontend/src/content/privacy.ts`, константа `OPERATOR`. Сейчас там «Сериков Марат» и контакты сайта; проверьте до запуска.
- **Изменили политику по существу** — поднимите дату версии в двух местах: `PRIVACY_VERSION` в `frontend/src/content/privacy.ts` и `PRIVACY_POLICY_VERSION` в `backend/app/config.py`. Каждого спросят снова, один раз.
- Текст составлен по Закону РК «О персональных данных и их защите», но это не юридическая консультация: перед открытым запуском его стоит показать юристу. Оферты (договора с ценами) пока нет — её пишут на ИП.

## Поурочные планы и язык объяснений

- **Длительность урока** — любая от 10 до 480 минут (8 часов). На странице есть 40, 45, 80 и 90 минут одной кнопкой и «Басқа» для своего числа. Этапы плана в сумме должны дать эту длительность (±10%), иначе агент отказывает, и единица тарифа возвращается.
- **Язык объяснения**: «Авто» (язык вопроса), қазақша, орысша или **English** — для школ вроде НЗМ, где часть предметов на английском. Вопрос можно задать на одном языке, а ответ получить на другом. Английская озвучка — голоса Aria и Guy из того же Azure. В видеотеке видео по одной теме лежат отдельно для каждого языка, и английский запрос не получит казахское видео.

## Задачи, система, метрики

**Задачи** (видят `admin` и `support`). Каждая генерация — видео, БЖБ/ТЖБ, план урока, квиз — это задача со статусом «в очереди → идёт → готово / ошибка», временем работы и типом ошибки:

| Тип ошибки | Что значит |
|---|---|
| превышено время | агент не ответил за отведённое время |
| агент отключился | связь с агентом пропала посреди работы; если он потом всё же пришлёт ответ, задача станет «готово» |
| агент недоступен | агента не было, когда задачу создали |
| не дошло до агента | запрос не подтвердился агентом |
| перезапуск сервера | бэкенд перезапустили, пока задача шла; единица тарифа возвращена учителю |
| негодный ответ модели | модель вернула то, что нельзя показать |
| `RenderError` и другие имена | ошибка внутри агента, имя класса исключения |

Неудачное видео или план урока можно **перезапустить**: делается заново для того же учителя и списывается с его тарифа (неудачная попытка была возвращена). Видео придёт в тот же чат, план — в список планов. Каждая задача перезапускается один раз. Фильтр «Только видео без звука» показывает видео, где озвучку заказали, а звука нет.

Текст вопроса хранится в задаче только пока он нужен для перезапуска: после успеха он удаляется сразу, после ошибки — через 14 дней. Сам вопрос остаётся в чате учителя. При удалении аккаунта задачи обезличиваются.

**Система** (видят оба). Подключён ли агент и его пульс (раз в 30 секунд: свободен или рендерит, сколько ждёт в очереди), сколько видео и документов в работе, самый старый запрос, место на диске, база данных. Сверху — предупреждения: агент не подключён или молчит больше двух минут, на диске меньше 10%, запрос ждёт больше 15 минут, за сутки 5 и больше ошибок.

**Метрики** (только `admin`). Воронка по учителям, зарегистрированным за период: регистрация → телефон → начали сынақ → что-то сделали → израсходовали → оплатили. Активные учителя за день, неделю и 30 дней. Выручка по месяцам. Рендеры видео по дням: сколько, ошибки, без звука, среднее время. Ошибки по типам.

**Упёрлись в лимит тарифа** (там же). По каждому ресурсу: сколько раз отказали, скольким учителям, из них на сынақ и на Ұстаз, и сколько учителей Ұстаз упёрлись **до 15-го дня** своего месяца подписки. Последнее — главный сигнал: если многие кончают ҚМЖ или БЖБ в первой половине месяца, лимит мал — поднимите его в «Тарифах». Отдельно — сколько упёрлись в потолок честного использования квизов.

**Azure TTS.** Бесплатный тариф Azure — 500 000 символов озвучки в месяц. Агент сообщает, сколько символов ушло на каждое видео, а метрики показывают сумму за месяц и прогноз к концу месяца. Это раннее предупреждение, точная цифра — в портале Azure. Если тариф Azure другой, поменяйте `AZURE_TTS_FREE_CHARS` в `.env`.

**Планы урока и квизы в фоне.** Cloudflare обрывает запрос через 100 секунд (ошибка 524), а план урока может писаться до 150 секунд. Поэтому страница отправляет запрос, сразу получает номер задачи и раз в 2,5 секунды спрашивает, готово ли. План сохраняется в списке, даже если учитель закрыл вкладку. Готовый черновик квиза ждёт, пока страница его заберёт, не больше часа.

## Ограничения и следующие задачи

- **БЖБ/ТЖБ пока ждёт ответа в самом запросе.** Его предел — 90 секунд, меньше 100 секунд Cloudflare, поэтому ошибки 524 нет. Если предел поднимут выше 100 секунд, БЖБ надо перевести в фон, как план урока и квиз.
- **Один домашний сервер — одна точка отказа.** Отключение света, интернета или Wi-Fi означает, что сайт недоступен. После включения всё поднимется само (`restart: unless-stopped`). Желательно поставить ИБП и, если возможно, подключить сервер по кабелю.
- **HDD** медленнее SSD: сборка, бэкапы и база работают дольше. Это не критично, но первая сборка долгая.
- **www** пока не настроен.
- **Анимации «как в монтажных роликах»** отложены: дольше рендер и дороже генерация. План — в `docs/MOTION_PLAN.md`.
- **Оплата полуручная** (см. «Оплата через Kaspi»): автосписаний нет, каждый платёж подтверждает человек. Автоподтверждение появится, когда будет договор с Kaspi или агрегатором платежей. Новые видео создают только учителя; ученикам доступны готовые ответы из библиотеки.
