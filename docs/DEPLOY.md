# Деплой на VPS

Весь стек живёт на одном сервере с Docker: тот же `docker-compose.yml`, что и
локально, плюс прод-слой `docker-compose.prod.yml`. Слой добавляет:
- сертификат Let's Encrypt, который продлевается сам;
- ночные бэкапы;
- сервис восстановления из бэкапа.

Мониторинг запускает cron на самом сервере и шлёт тревоги в Telegram.

Подходит любой VPS с Linux и Docker. Код переписывать не нужно.

```
                    ┌──────────────────────── VPS ────────────────────────┐
 браузер ─:443/:80─►│ frontend (nginx, TLS) ─► backend ─► mongo           │
                    │                         ─► quiz     ▲               │
                    │ agent ◄─ws─ backend     exporter ───┘               │
                    │ certbot (продлевает)    backup ─► /var/backups/anyq │
                    └─────────────────────────────────────────────────────┘
                      cron: deploy/monitor.sh ─► Telegram
```

## Что нужно заранее

**Сервер.**

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| vCPU | 4 | 8 |
| RAM | 8 ГБ | 16 ГБ |
| Диск | 60 ГБ SSD | — |

Основную нагрузку дают рендер видео (агенту выделено до 2 CPU и 2 ГБ), база (до 2 ГБ) и экспорт (до 1,5 CPU). Сборка образа агента с LaTeX занимает около 10 ГБ диска.

Подойдёт любой Linux с Docker Engine 24+ и Compose v2. Скрипты рассчитаны на Ubuntu 22.04/24.04 и Debian 12.

**Сервер в Казахстане.** По правилам домена `.kz` сайт должен размещаться на оборудовании в РК. Закон о персональных данных требует, чтобы базы с ними тоже были в РК. Подходят PS Cloud, Hoster.kz или Yandex Cloud с регионом в Алматы.

**DNS.** У регистратора домена нужны две A-записи на IP сервера: `akronai.kz` и `www.akronai.kz`.

**Порты.** 80 и 443 должны быть открыты в панели хостера, если у него есть свой фаервол.

**Новые ключи.** Нужны OpenRouter и Azure Speech, плюс Gemini, если нужен разбор скриншотов. Старые ключи засвечены, поэтому сначала отзовите их, потом выпустите новые.

## Первый запуск

Все команды выполняются на сервере под root (`sudo -i`).

**1. Docker**, если его ещё нет. Официальный способ: https://docs.docker.com/engine/install/. На Ubuntu и Debian он сводится к одной команде:

```bash
curl -fsSL https://get.docker.com | sh
```

**2. Код.** Репозиторий приватный. Добавьте серверу deploy key: на сервере выполните `ssh-keygen -t ed25519`, затем в GitHub откройте Settings → Deploy keys → Add и включите только чтение.

```bash
git clone git@github.com:makserik1999-web/qwerty-AI.git /opt/anyq
cd /opt/anyq
git checkout feat/f0-frontend-merge   # пока ветка не влита в main
```

**3. Сервер вокруг стека.** Скрипт создаёт swap 4 ГБ, если его нет, каталог бэкапов, задание cron для мониторинга и настраивает фаервол. Фаервол открывает только SSH, 80 и 443.

```bash
bash deploy/prepare-server.sh --firewall
```

**4. Файл `.env`.** Скрипт генерирует все пароли и секреты, включает HTTPS и прописывает домен.

```bash
bash deploy/init-env.sh akronai.kz you@example.com
nano .env      # вписать OPENROUTER_API_KEY, AZURE_SPEECH_KEY, AZURE_SPEECH_REGION, TELEGRAM_*
```

**5. Сертификат.** Скрипт проверяет DNS и порт 80, получает сертификат и включает HTTPS. Запуск означает согласие с [условиями Let's Encrypt](https://letsencrypt.org/repository/).

```bash
bash deploy/init-tls.sh --staging   # тренировка на тестовом сертификате (по желанию)
bash deploy/init-tls.sh --force     # настоящий сертификат после --staging
bash deploy/init-tls.sh             # или сразу настоящий
```

**6. Запуск.** Скрипт проверяет `.env`, собирает образы, поднимает стек, ждёт, пока все сервисы станут healthy, и проверяет сайт снаружи. Первая сборка занимает 10–20 минут, почти всё время уходит на агента.

```bash
bash deploy/deploy.sh
```

**7. Проверка тревог.** Должно прийти сообщение в Telegram:

```bash
bash deploy/monitor.sh --test
```

**8. Внешняя проверка.** Мониторинг работает на том же сервере, поэтому падение самого сервера он не заметит. Заведите бесплатную проверку `https://akronai.kz/` раз в 5 минут в UptimeRobot или Better Stack.

## Обновление

```bash
cd /opt/anyq
bash deploy/deploy.sh --pull
```

Пересоздаются только изменённые контейнеры. Несколько секунд сайт может отвечать 502, сокеты квизов переподключаются сами. Обновляйте вне уроков.

## Бэкапы

**Что и когда.** Каждую ночь в 02:00 по Астане (`BACKUP_HOUR_UTC=21`) сервис `backup` делает дамп базы. Видео он зеркалирует рядом. Дампы хранятся 14 дней (`BACKUP_KEEP_DAYS`). При первом запуске дамп делается сразу.

**Где лежат.** Всё в `/var/backups/anyq` на хосте, вне томов Docker: `docker compose down -v` бэкапы не удалит.
- `mongo/anyq-<время UTC>.archive.gz` — дампы базы;
- `media/outputs/` — зеркало видео;
- `media-removed/<дата>/` — видео удалённых аккаунтов. Они хранятся столько же, сколько дампы, потом стираются.

**Сделать бэкап сейчас:**

```bash
docker compose exec backup bash /opt/anyq/backup.sh once
```

**Восстановить.** Перед восстановлением скрипт сам делает свежий бэкап и спрашивает домен для подтверждения.

```bash
bash deploy/restore.sh                                     # список дампов
bash deploy/restore.sh anyq-20261004-210000.archive.gz     # восстановить
```

**Копия бэкапов.** Бэкапы на том же диске, что и база, погибнут вместе с сервером. Копируйте их в другое место по схеме pull: другая машина сама забирает файлы, а сервер к ней доступа не имеет. Тогда взломанный сервер не сможет стереть копии. Например, cron на домашнем компьютере или втором VPS:

```bash
rsync -az root@akronai.kz:/var/backups/anyq/ ~/anyq-backups/
```

Можно также включить снапшоты диска у хостера, если они есть. Раз в месяц проверяйте, что бэкап восстанавливается, хотя бы на тестовой машине.

**Перенести базу с другой машины.**

1. На локальной машине, при запущенном стеке, сделайте архив. Папка должна лежать вне репозитория, чтобы данные случайно не попали в коммит:

   ```bash
   BACKUP_DIR=$HOME/anyq-export docker compose -f docker-compose.yml -f docker-compose.prod.yml run --rm --no-deps backup once
   ```

2. Скопируйте архив на сервер:

   ```bash
   scp -r ~/anyq-export/* root@akronai.kz:/var/backups/anyq/
   ```

3. На сервере запустите `bash deploy/restore.sh <файл>`.

## Мониторинг

Cron запускает `deploy/monitor.sh` каждые 5 минут и проверяет:
- все сервисы запущены и healthy. Сюда входят связь агента с бэкендом и бэкап за последние 26 часов;
- снаружи отвечают сайт, API и квизы;
- до конца срока сертификата больше 14 дней;
- диск занят меньше чем на 85%.

Сообщение приходит, когда набор проблем меняется, и напоминание каждые 6 часов, пока проблема не ушла. Лог пишется в `/var/log/anyq-monitor.log`.

**Telegram.**
1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен в `TELEGRAM_BOT_TOKEN`.
2. Напишите боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<токен>/getUpdates` и возьмите оттуда `chat.id` в `TELEGRAM_CHAT_ID`.

## Сертификат

Сервис `certbot` дважды в день проверяет срок и продлевает сертификат за 30 дней до конца. Nginx замечает новый файл в течение часа и перезагружается сам, без обрыва соединений.

Проверить продление вхолостую:

```bash
docker compose exec certbot certbot renew --dry-run --webroot -w /var/www/acme
```

## Полезное

```bash
docker compose ps                      # состояние
docker compose logs -f backend         # логи сервиса
docker compose restart agent           # перезапустить один сервис
docker image prune -f                  # старые образы после обновлений
docker builder prune -f                # кэш сборки, если кончается диск
```

`COMPOSE_FILE` в `.env` уже включает прод-слой, поэтому флаги `-f` на сервере не нужны.

## Безопасность: чек-лист

- [ ] Старые ключи Azure и OpenRouter отозваны, в `.env` новые.
- [ ] В SSH вход только по ключу: `PasswordAuthentication no` в `/etc/ssh/sshd_config`.
- [ ] Включены автообновления безопасности: `apt install unattended-upgrades`.
- [ ] `.env` с правами 600 лежит только на сервере (`deploy.sh` следит за правами).
- [ ] Снаружи открыты только 22, 80 и 443. Mongo на хост не опубликована: `ss -tlnp` её не показывает.
- [ ] `deploy.sh` проверил, что `/ws/agent` снаружи отвечает 403.
- [ ] Заголовок HSTS включён с `includeSubDomains` на год. Любой поддомен `akronai.kz` после этого обязан работать по HTTPS.

## Чего здесь нет

- **Один сервер — одна точка отказа.** Агент рендерит по одному видео за раз (`GENERATION_MAX_CONCURRENT=1`). Масштабирование — отдельная задача.
- **Автодеплоя из GitHub нет.** Обновление делается вручную через `deploy.sh --pull`.
- **Оплаты нет.** Страница «Баланс» пока на демо-данных.

| `deploy/restore.sh` | восстанавливает из бэкапа (сначала делает свежий бэкап) |

| `deploy/prepare-server.sh` | swap, каталог бэкапов, cron, фаервол |
| `deploy/backup.sh` | работает внутри контейнеров backup и restore, не на хосте |
